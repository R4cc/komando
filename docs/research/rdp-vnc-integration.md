# RDP and VNC integration research

Researched 2026-11-12. Research only: no implementation, builds, tests, remote desktop connections, or server changes. **Source facts** below describe inspected code/documentation; **proposals** and **untested assumptions** describe possible Komando work.

## Recommendation

**Proposal:** prefer IronRDP for RDP and HsuJv/vnc-rs for VNC, feeding a shared native GPUI desktop view. Display each desktop as a Session beneath its Host, alongside independent SSH Sessions. This best preserves native composition, Vault ownership, and the existing Host-first workflow. It is a conditional architecture recommendation, not a claim that either engine already meets every target's requirements.

The main gates are secure RDP certificate handling, actual Windows/xrdp compatibility, VNC authentication compatibility, and sustained GPUI framebuffer performance. For Windows-focused RDP compatibility, prototype Microsoft's MsTscAx ActiveX control as the strongest alternative. A mixed implementation—ActiveX RDP plus native Rust VNC—is reasonable if the control's hosting behavior passes review. Keep an external viewer option for unsupported targets. Do not select a web gateway by default.

## Existing Komando constraints: local source facts

Komando ships for Windows 11, uses embedded russh SSH, and deliberately chose native GPUI over a web UI for performance. The inspected package is 0.3.3, with gpui-pre 0.3.12, gpui-component 0.9.1, and Tokio. These are architecture constraints, not reasons to assume that any new desktop backend is fast. Sources: [Windows ADR](/home/codex/.t3/projects/komando/docs/adr/0001-windows-11-only.md), [SSH ADR](/home/codex/.t3/projects/komando/docs/adr/0002-embedded-ssh-client.md), [UI ADR](/home/codex/.t3/projects/komando/docs/adr/0003-native-gpu-ui.md), [manifest](/home/codex/.t3/projects/komando/Cargo.toml).

The Host stores an SSH address/port and inherited user, Credential, and Jump Host references. The Vault supports passwords and private keys; definitions contain references, never secret values. `SessionEntry` owns `Entity<TerminalView>` and SSH-specific file-browser state. Adding desktop enum variants alone would therefore be insufficient: desktop rendering and lifecycle need a different view abstraction. Sources: [Host](/home/codex/.t3/projects/komando/src/model.rs:149), [Vault](/home/codex/.t3/projects/komando/src/vault.rs:45), [SessionEntry](/home/codex/.t3/projects/komando/src/ui/workspace.rs:144), [Vault ADR](/home/codex/.t3/projects/komando/docs/adr/0004-master-password-vault.md).

The sidebar already groups multiple Sessions under a Host. Desktop Sessions extend that model; top tabs are not required. The glossary currently defines Host and Session in SSH/terminal terms, so implementation would need a deliberate vocabulary update, including desktop behavior after disconnect. Sources: [sidebar ADR](/home/codex/.t3/projects/komando/docs/adr/0005-sidebar-lists-hosts-not-sessions.md), [glossary](/home/codex/.t3/projects/komando/GLOSSARY.md).

## Implementation choices

| Choice | Protocols and UI ownership | Principal benefit | Burden / decision gate |
| --- | --- | --- | --- |
| IronRDP + vnc-rs | RDP + VNC; Komando paints pixels and maps input | Shared GPUI composition and transport architecture | Security/feature gaps, decoding, clipboard, rendering performance |
| Microsoft ActiveX + VNC engine | RDP in child HWND; separate VNC renderer | Microsoft implements the RDP client | Rust COM/OLE host, events, focus, clipping, DPI, component availability |
| FreeRDP library + VNC engine | RDP via C library; custom frontend | Established RDP implementation and channel support | C/native dependency packaging and unsafe FFI lifecycle |
| LibVNCClient | VNC library; custom frontend | Broader VNC security/encoding coverage | GPL-2.0-or-later distribution review and native builds |
| WebView2 + noVNC | VNC web view; another engine needed for RDP | Existing browser-oriented viewer | WebSocket bridge, browser runtime, ADR exception |
| WebView2 + Guacamole | Both through backend gateway | One web frontend for both protocols | Gateway deployment, credentials, reachability, operations |
| External mstsc / configured VNC viewer | Separate process/window | Practical compatibility fallback | Viewer installation, fragmented lifecycle and credential handoff |

### Native Rust engines

**IronRDP facts:** the project is MIT OR Apache-2.0. Its architecture separates protocol state machines, session/graphics processing, and channel implementations. Current `ironrdp-client` exposes runtime input/output events independently of winit, using a bounded Tokio output channel. This is a much closer embedding seam than adopting a whole GUI client. Sources: [IronRDP manifest](https://github.com/Devolutions/IronRDP/blob/0a79fd2178c79b3d8920b6e76f2a9da5db6331ca/Cargo.toml), [architecture](https://github.com/Devolutions/IronRDP/blob/0a79fd2178c79b3d8920b6e76f2a9da5db6331ca/ARCHITECTURE.md), [client API overview](https://github.com/Devolutions/IronRDP/blob/0a79fd2178c79b3d8920b6e76f2a9da5db6331ca/crates/ironrdp-client/README.md).

CredSSP/NLA code supports password authentication with NTLM and configurable Kerberos. Clipboard and display-control implementations exist; their presence does not prove a complete Windows clipboard adapter or universal live resize. The embedder must connect negotiated capabilities to UI behavior. Sources: [CredSSP](https://github.com/Devolutions/IronRDP/blob/0a79fd2178c79b3d8920b6e76f2a9da5db6331ca/crates/ironrdp-connector/src/credssp.rs), [clipboard](https://github.com/Devolutions/IronRDP/tree/0a79fd2178c79b3d8920b6e76f2a9da5db6331ca/crates/ironrdp-cliprdr), [display control](https://github.com/Devolutions/IronRDP/blob/0a79fd2178c79b3d8920b6e76f2a9da5db6331ca/crates/ironrdp-displaycontrol/src/client.rs).

**Security gate:** certificate validation is disabled by default in the inspected TLS library. Explicit strict validation checks platform roots and server name; the Rustls backend offers a callback for a deliberate trust decision after failure. Komando must provide a certificate-change/trust policy rather than blindly accepting certificates. The native TLS callback has limitations. These APIs were also found in the published [ironrdp-tls 0.3.0 package](https://crates.io/api/v1/crates/ironrdp-tls/0.3.0/download). See [TLS documentation](https://github.com/Devolutions/IronRDP/blob/0a79fd2178c79b3d8920b6e76f2a9da5db6331ca/crates/ironrdp-tls/README.md).

Do not describe the complete integration as pure Rust or dependency-free: current graphics can use Windows Media Foundation or bundled OpenH264; optional audio and other redirection have native backends. Select a minimal feature set and review its complete dependency/license graph. Advanced authentication is not automatic parity with mstsc: current Entra documentation explicitly identifies experimental and unverified live-host behavior. Sources: [client features](https://github.com/Devolutions/IronRDP/blob/0a79fd2178c79b3d8920b6e76f2a9da5db6331ca/crates/ironrdp-client/Cargo.toml), [client limitations](https://github.com/Devolutions/IronRDP/blob/0a79fd2178c79b3d8920b6e76f2a9da5db6331ca/crates/ironrdp-client/README.md).

**vnc-rs facts:** async client engine, MIT OR Apache-2.0, with Raw, CopyRect, Tight, and ZRLE paths. Its README reports older TightVNC/macOS server trials, untested TRLE, and no Hextile/RRE implementation. Limits include 8,294,400 framebuffer pixels, 8192 per axis, and 1 MiB clipboard messages; these are not an application memory budget. Sources: [README](https://github.com/HsuJv/vnc-rs/blob/74c388745b9ca22099277480c3c6f34522b2f1d4/README.md), [manifest](https://github.com/HsuJv/vnc-rs/blob/74c388745b9ca22099277480c3c6f34522b2f1d4/Cargo.toml).

The inspected connector implements None, classic VNC password authentication, and an explicit Apple ARD path. TLS/VeNCrypt enum entries are **not implementations**: unsupported negotiations fail. It also prefers None when offered in the legacy path, requiring policy review before adoption. A generic async stream could carry an SSH tunnel, but wrapping TCP in TLS does not implement VeNCrypt negotiation. Sources: [connector](https://github.com/HsuJv/vnc-rs/blob/74c388745b9ca22099277480c3c6f34522b2f1d4/src/client/connector.rs), [auth](https://github.com/HsuJv/vnc-rs/blob/74c388745b9ca22099277480c3c6f34522b2f1d4/src/client/auth.rs).

Classic VNC authentication does not encrypt subsequent desktop traffic. Require an appropriate protected transport; an SSH tunnel ending on a separate Jump Host leaves its onward plain-VNC hop outside SSH protection. Source: [RFB security considerations](https://www.rfc-editor.org/rfc/rfc6143.html#section-9); the hop implication follows from the proposed transport layout.

The event interface exposes framebuffer rectangles, cursor and clipboard events, and encoded JPEG rectangles requiring frontend decoding. Clipboard is documented as Latin-1, not arbitrary Unicode. Current code includes a negotiated single-screen `resize_desktop`, with unsupported/denied/timeout outcomes; that is separate from simply scaling an image. Sources: [events](https://github.com/HsuJv/vnc-rs/blob/74c388745b9ca22099277480c3c6f34522b2f1d4/src/event.rs), [resize](https://github.com/HsuJv/vnc-rs/blob/74c388745b9ca22099277480c3c6f34522b2f1d4/src/client/resize.rs), [connection API](https://github.com/HsuJv/vnc-rs/blob/74c388745b9ca22099277480c3c6f34522b2f1d4/src/client/connection.rs).

**Version caution:** moving documentation can lag registry publication. The registry returned vnc-rs 0.6.1 during research; its archive was inspected in memory and contains ARD and resize code. Its VCS metadata names `24aa0072…`, whose GitHub raw URL was unavailable. Earlier 0.6.0 lacks the ARD connector path. IronRDP master findings are pinned above to `0a79fd21…`; they must not all be attributed to published `ironrdp-client` 0.1.0. A later prototype must choose and audit exact compatible releases. Sources: [vnc-rs registry metadata](https://crates.io/api/v1/crates/vnc-rs), [0.6.1 archive](https://crates.io/api/v1/crates/vnc-rs/0.6.1/download), [IronRDP client archive](https://crates.io/api/v1/crates/ironrdp-client/0.1.0/download).

Do not substitute `rustvncserver`: its published API is a server library, not a drop-in viewer. Source: [author's crate documentation](https://docs.rs/crate/rustvncserver/2.2.1).

### Microsoft ActiveX RDP

Microsoft documents RDP control interfaces for configuration, connection/disconnection, events, redirection and RD Gateway. Non-scriptable, write-only `ClearTextPassword` accepts a password before connecting, allowing a transient Vault-to-COM handoff without a password file or CLI argument. Komando must still manage plaintext lifetime; COM/control copies are outside Rust's zeroizing wrapper. Sources: [interfaces](https://learn.microsoft.com/en-us/windows/win32/termserv/remote-desktop-web-connection-reference), [password API](https://learn.microsoft.com/en-us/windows/win32/termserv/imstscnonscriptable-cleartextpassword).

Server-authentication policy and clipboard redirection are configurable. SmartSizing scales locally; `UpdateSessionDisplaySettings` updates remote display settings, subject to control/server support. Sources: [server authentication](https://learn.microsoft.com/en-us/windows/win32/termserv/imsrdpclientadvancedsettings4-authenticationlevel), [clipboard](https://learn.microsoft.com/en-us/windows/win32/termserv/imsrdpclientadvancedsettings5-redirectclipboard), [SmartSizing](https://learn.microsoft.com/en-us/windows/win32/termserv/imsrdpclientadvancedsettings-smartsizing), [display update](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/legacy/mt703457(v=vs.85)).

Microsoft also documents a [CredSSP setting](https://learn.microsoft.com/en-us/windows/win32/termserv/imsrdpclientadvancedsettings6-enablecredsspsupport), with old client-version qualifications. Verify the installed control's supported interfaces, NLA/TLS behavior and intended account types; do not assume every modern mstsc authentication feature is exposed identically through ActiveX.

**Untested integration:** host the control in a Komando-owned child HWND with COM/OLE site interfaces, event sinks, keyboard routing, geometry and teardown. GPUI's Windows platform already calls `OleInitialize`, but this is not an ActiveX container implementation. Its child HWND needs explicit hide/clipping behavior when dialogs or another Session occupy the pane. Microsoft's WPF airspace explanation illustrates mixed-HWND composition constraints; applying that concern to GPUI is an inference, not a claim GPUI is WPF. Sources: [local OLE initialization](/home/codex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/gpui-pre-windows-0.3.12/src/platform.rs:186), [airspace](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/technology-regions-overview?view=netframeworkdesktop-4.8).

Treat MsTscAx as a Microsoft component to detect and activate, with interface-version checks and a missing-component fallback. Availability on supported Windows images and any redistribution rights require verification; an SDK reference is not a blanket license to bundle the DLL. This option avoids implementing RDP, not hosting engineering.

### C libraries, web views, and external viewers

**FreeRDP:** Apache-2.0 RDP implementation with NLA/TLS, clipboard and display-control source. It can underpin a custom view, but Rust must own callback safety, buffers, threading and teardown across FFI. Its CMake build includes crypto, compression and optional codecs; packaging exact Windows libraries becomes Komando's responsibility. Sources: [project](https://github.com/FreeRDP/FreeRDP), [NLA](https://github.com/FreeRDP/FreeRDP/blob/master/libfreerdp/core/nla.c), [TLS](https://github.com/FreeRDP/FreeRDP/blob/master/libfreerdp/crypto/tls.c), [clipboard](https://github.com/FreeRDP/FreeRDP/blob/master/channels/cliprdr/client/cliprdr_main.c), [resize](https://github.com/FreeRDP/FreeRDP/blob/master/channels/disp/client/disp_main.c), [build documentation](https://github.com/FreeRDP/FreeRDP/wiki/Compilation).

**LibVNCClient:** broader advertised security includes TLS, VeNCrypt, SASL and Apple ARD; encoding and crypto support depend on build options. Its GPL-2.0-or-later license requires distribution review against Komando's intended license, which was not declared in the inspected root manifest and had no root LICENSE file. This is a research flag, not a legal conclusion. Source: [upstream support/build/license documentation](https://github.com/LibVNC/libvncserver/blob/master/README.md).

**WebView2/noVNC:** noVNC is VNC-only, mainly MPL-2.0, with scaling/resize/clipboard features. It requires a WebSocket-capable VNC endpoint or WebSocket-to-TCP bridge. Such a bridge could be local; no Internet service is inherently required. RDP needs another implementation, such as IronRDP WASM plus transport bridge, or Guacamole. Sources: [noVNC](https://github.com/novnc/noVNC), [IronRDP web component](https://github.com/Devolutions/IronRDP/tree/0a79fd2178c79b3d8920b6e76f2a9da5db6331ca/crates/ironrdp-web).

Guacamole puts protocol connections in `guacd` behind a web/backend layer; its gateway must reach the hosts and participates in credential handling. It is not a local offline embedding library. Its client uses Apache-2.0 with bundled third-party notices. WebView2 adds runtime distribution and native hosting/input decisions. This would deliberately reopen ADR 0003, with performance measured later. Sources: [Guacamole architecture](https://guacamole.apache.org/doc/gug/guacamole-architecture.html), [client license](https://github.com/apache/guacamole-client/blob/main/LICENSE), [WebView2 distribution](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution), [hosting modes](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/windowed-vs-visual-hosting).

**External fallback:** mstsc officially accepts `/v:server[:port]` and `.rdp` files, but its documented syntax has no password switch. Use nonsecret settings and normal authentication; Windows Credential Manager handoff would change ADR 0004's Vault boundary. Never recommend password command-line arguments. A configured VNC viewer needs its own verified launch/auth contract. Reparenting mstsc with `SetParent` is a fragile primary design: Microsoft documents style/UI-state obligations and DPI mismatch failures/resets; cross-process focus and lifecycle remain additional concerns. Sources: [mstsc](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/mstsc), [SetParent](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent).

## UI choices: proposals, not industry findings

| Presentation | Use and tradeoff |
| --- | --- |
| **Main-pane desktop Session: recommended** | Familiar Host/sidebar grouping, maximum useful area, small protocol/identity toolbar. SSH, RDP and VNC remain distinct Sessions. |
| SSH + desktop split | Useful during administration; later optional layout with independent focus and sizing. Less desktop area and more input-state complexity. |
| Komando-owned popout window | Useful on another monitor; requires window ownership, reconnect/close behavior and DPI transitions. |
| Overview thumbnails | Useful for many hosts; later feature requiring update throttling, explicit resource budgets and privacy decisions. |
| External viewer window | Compatibility escape hatch; visibly identified as external, without implying embedded Session control. |

**Configuration:** progressively disclose “Enable RDP” and “Enable VNC” in the Host form. Each gets endpoint/port, optional address override, account/domain where applicable, compatible Vault Credential reference, display mode and transport route. Preserve existing SSH fields/defaults and backward deserialization. One Host may enable all three protocols; SSH-only Hosts need no desktop setup. Private-key SSH Credentials are not automatically desktop passwords.

**One-click behavior:** provide explicit SSH/RDP/VNC actions and a configurable Host default action; selecting an existing desktop Session focuses it, while creating another is explicit. After configuration, one click starts the selected protocol. Vault unlock, new/changed server identity consent, interactive sign-in or server policy can still require interaction.

**Desktop controls:** fit/actual-size, fullscreen, disconnect/reconnect, view-only and text-clipboard policy. Show effective host, protocol and transport identity. Separate local scaling from negotiated remote resize. On disconnect, propose a clearly marked frozen frame with input disabled and reconnect; it is not terminal Scrollback. A retained frame may contain sensitive data; persistence should require a separate decision. An ActiveX freeze-frame capture is unverified and may need a disconnected placeholder instead.

Input capture needs a visible local escape command, documented shortcut routing and modifier/button release on focus loss. Do not promise Ctrl+Alt+Del, IME, touch or multi-monitor behavior before verifying the selected engine APIs and Windows behavior.

## Transport and server boundaries

**Local fact:** Jump Hosts use russh `direct-tcpip` and `Channel::into_stream`. **Untested proposal:** reuse that route for desktop streams; ActiveX/external viewers would generally need session-scoped loopback forwarding. Bind only loopback, manage listener lifetime, and keep the original RDP server name for TLS/NLA/SPN even when the socket connects locally. IronRDP explicitly distinguishes actual server identity from proxy identity. RD Gateway is a separate transport, not an SSH Jump Host. Sources: [SSH tunnel](/home/codex/.t3/projects/komando/src/session/ssh.rs:264), [Jump Host ADR](/home/codex/.t3/projects/komando/docs/adr/0006-jump-hosts-in-the-embedded-client.md), [CredSSP identity](https://github.com/Devolutions/IronRDP/blob/0a79fd2178c79b3d8920b6e76f2a9da5db6331ca/crates/ironrdp-connector/src/credssp.rs).

Komando cannot make an SSH-only server accept desktop connections. Windows targets require a supported host edition, enabled RDP and permitted accounts; Home cannot host RDP. Personal Windows sign-in, console switching and concurrent-user behavior must be checked explicitly, not treated as VNC-style shared-console access. Linux xrdp requires desktop/server components and advertises TLS, resizing and clipboard capabilities, which still need client interoperability checks. VNC deployments may require security modes vnc-rs lacks. Sources: [Windows prerequisites](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/remotepc/remote-desktop-allow-access), [Windows session switching](https://learn.microsoft.com/en-us/windows/win32/shell/fastuserswitching), [xrdp](https://github.com/neutrinolabs/xrdp), [TigerVNC security options](https://tigervnc.org/doc/vncviewer.html).

## Later prototype and acceptance questions

No prototype is authorized by this report. After implementation permission:

1. Define actual target servers/security modes. Check Windows local/domain sign-in, NLA and certificate rejection/change; xrdp login/reconnect; TigerVNC and intended hypervisor-console encodings/security. Do not weaken servers merely to fit a client.
2. Compare the minimal IronRDP adapter with an ActiveX hosting experiment. Verify authentication, events, focus, overlays, mixed DPI, hide/show, teardown and missing-component fallback. Choose based on evidence, not assumed feature parity.
3. Prove GPUI framebuffer lifetime/performance. `paint_image` uses `RenderImage` and a sprite atlas, with `drop_image` available; this is not a demonstrated zero-copy streaming API. Measure dirty-update coalescing, texture/cache reclamation, bounded queues, background Sessions, memory, CPU/GPU load and input latency. Preserve ordered CopyRect updates. Source: [pinned local renderer API](/home/codex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/gpui-pre-0.3.12/src/window.rs:5303).
4. Verify input coordinates at fit/actual-size and mixed DPI; keyboard layouts, focus-loss releases, local escape, view-only and clipboard limits/Unicode. Confirm remote resize rejection falls back to scaling without reconnect loops.
5. Verify tunnel identity, Vault locking/cancellation, no secret logging/files, route cleanup, old-library compatibility and precise failure messages. Audit exact dependency versions, notices and distribution obligations before shipping.

No FPS, latency, build-size, feature-parity, time or cost estimates were measured. Backend choice, secure VNC coverage and GPUI streaming feasibility remain open until those gates pass.
